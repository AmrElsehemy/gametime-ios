# Knowlly Games — 50 Day Launch Roadmap

## Day 1 — Foundation exists

Outcome:
- repositories initialized
- Xcode workspace / Swift package builds
- GameTimeKit skeleton exists
- Game #001 shell exists
- basic web presence deployed
- naming/repo conventions frozen

Do not polish.

## Day 2 — Game #001 is playable

Outcome:
- core mechanic works end-to-end on iPhone
- input, validation, win, reset, next level
- first five levels
- haptic + basic sound
- one satisfying completion animation

## Day 3 — It feels like a game

Outcome:
- levels 1–5 teach through play
- persistence/progression
- 20–30 levels
- proper juice, audio and haptics
- undo/hint framework
- replay logging foundation
- visual direction selected

## Day 5 — Internal TestFlight product

Outcome:
- 50–100 validated/curated levels where appropriate
- polished onboarding
- analytics
- crash diagnostics
- Game Center skeleton
- rewarded-ad test mode
- StoreKit test product
- settings/support/privacy surfaces
- replay/debug package
- performance checks

## Day 10 — Submitted to Apple

Outcome:
- App Store screenshots/preview
- description/keywords/metadata
- privacy/support URLs
- Game Center leaderboard/achievements where relevant
- rewarded ads production-configured
- Remove Ads IAP
- first launch creatives
- App Store submission complete

Apple review duration is external to this roadmap.

## Day 20 — First learning loop

Target:
- Game #001 public if Apple review permits
- real retention/monetization data arriving
- Game #002 in TestFlight or submission
- Game #002 proves GameTimeKit creates material reuse
- initial Knowlly Games social publishing active

## Day 30 — Studio is visible

Target:
- 2–3 public games
- knowlly.games portfolio live
- shared support/privacy/analytics/release pipeline
- social capture → templating/Remotion → scheduling increasingly automated
- small paid acquisition experiments only on titles with supporting organic evidence

## Day 50 — The factory exists

Target:
- 4 public games; stretch 5–6 only if reuse truly supports it
- Game #001 has data-driven updates
- at least one harder mechanic family underway
- shared monetization/tutorial/replay/diagnostics/remote-config/Game Center/release/marketing capabilities proven across titles
- owner receives portfolio briefs and approval gates rather than manually operating every app

## Operating constraint

Every task must answer one of these questions:

1. Does this directly help ship Game #001?
2. Does this materially make Game #002 faster?

If neither, backlog it.

Do not allow Game #002 to become the focus before Game #001 is submitted.
